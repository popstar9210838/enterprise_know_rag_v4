# 研发流程与技术规范

## 研发流程总览
公司采用双轨研发模式：产品迭代轨道（每两周一个 Sprint）和技术创新轨道（每季度一个研究周期）。

## 需求到上线的完整流程

### 需求阶段
产品经理从客户反馈、数据分析、竞品调研中提炼需求，编写 PRD。PRD 须包含需求背景、用户场景、功能描述、交互原型和验收标准。

### 设计阶段
UX 设计师输出高保真交互原型和视觉设计稿。技术 Lead 编写技术方案（Design Doc），包括架构设计、数据库设计、接口定义、影响范围评估。开发量超过 5 人天的需求须经过技术评审。

### 开发阶段
开发人员按技术方案编码，遵循公司编码规范。所有代码须通过 Code Review（至少 1 名 Reviewer Approve）方可合并。Review 重点：逻辑正确性、安全性、性能、可维护性。

### 测试阶段
QA 工程师编写测试用例，执行功能测试、回归测试。关键需求额外执行探索性测试和安全测试。

### 发布阶段
采用灰度发布策略：1% → 10% → 50% → 全量逐级放量。每级灰度持续观察至少 30 分钟。异常时立即回滚。

## 编码规范
- 单个函数不超过 80 行，单个文件不超过 500 行
- 注释率不低于 15%，公共 API 必须有文档注释
- 禁止硬编码密钥和密码
- 数据库操作使用参数化查询，禁止拼接 SQL
- 使用结构化日志（JSON 格式），包含 traceId、spanId

## 技术债务管理
技术债务统一登记在 Jira Backlog 中。每个 Sprint 分配不少于 15% 的开发资源用于偿还技术债务。每季度进行一次技术债务集中评估和清理。

## 知识沉淀
所有项目和系统必须在公司 Wiki 上维护架构文档、部署文档和运维手册。关键技术决策须记录 ADR（Architecture Decision Record）。
